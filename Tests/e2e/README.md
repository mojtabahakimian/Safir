# تست سرتاسری (E2E) با Playwright

برنامه را در یک مرورگر واقعی بالا می‌آورد و همان کارهایی را می‌کند که یک آدم
می‌کند: وارد می‌شود، بین بخش‌ها می‌رود، دکمه می‌زند، و می‌بیند چه چیزی نمایش
داده می‌شود.

## اجرا

```bash
# ۱. برنامه باید در حال اجرا باشد
cd Server && dotnet run          # یا: dotnet bin/Debug/net8.0/Safir.Server.dll

# ۲. تست‌ها
cd Tests/e2e
npm install
npx playwright test              # همه
npx playwright test --headed     # با دیدن مرورگر
npx playwright show-report       # گزارش HTML آخرین اجرا
```

آدرس برنامه پیش‌فرض `http://127.0.0.1:5080` است و با `APP_URL` عوض می‌شود.

## دو دسته تست

| فایل | نیاز به دیتابیس | چه چیزی را ثابت می‌کند |
|---|---|---|
| `tests/01-smoke.spec.js` | ❌ ندارد | برنامه واقعاً در مرورگر بالا می‌آید، RTL است، و لایه‌ی احراز هویت کار می‌کند |
| `tests/02-acl.spec.js` | ✅ دارد | سه کاربر با نقش‌های متفاوت دقیقاً چیزی را می‌بینند و می‌توانند که باید |

تست‌های گروه دوم اگر دیتابیس نباشد **skip** می‌شوند، نه fail. این عمدی است:
اگر شکستِ محیط با شکستِ برنامه قاطی شود، دیگر کسی به گزارش تست اعتماد
نمی‌کند. برای فعال شدنشان اول این را اجرا کنید:

```bash
./scripts/setup-test-env.sh
```

## چرا فقط چک کردن «/ کد ۲۰۰ می‌دهد» بی‌فایده است

در Blazor WebAssembly صفحه‌ی اول یک فایل استاتیک `index.html` است. حتی وقتی
دیتابیس خاموش و کل API خراب باشد هم ۲۰۰ برمی‌گرداند. پس این تست هیچ چیزی را
ثابت نمی‌کند.

آنچه واقعاً بررسی می‌شود:

1. `_framework/blazor.boot.json` سالم است و بیش از ۵۰ اسمبلی دارد
2. متن‌هایی که **داخل کامپوننت‌ها** هستند در مرورگر رندر می‌شوند —
   یعنی runtime دات‌نت واقعاً اجرا شده
3. `POST /api/auth/login` توکن می‌دهد — یعنی دیتابیس، Dapper، JWT و
   کدگشایی رمز همه کار می‌کنند
4. endpointهای محافظت‌شده بدون توکن ۴۰۱ و با توکن دستکاری‌شده هم ۴۰۱ می‌دهند

## نکته‌ی مرورگر

بعضی محیط‌ها (Jules، Claude Code on the web) Chromium را از قبل در
`PLAYWRIGHT_BROWSERS_PATH` دارند ولی شماره‌ی build آن با نسخه‌ی
`@playwright/test` نصب‌شده یکی نیست، و Playwright ادعا می‌کند مرورگر نصب
نیست. `playwright.config.js` خودش دنبال Chromium موجود می‌گردد و مسیرش را
می‌دهد، پس نیازی به `npx playwright install` نیست. اگر لازم شد با
`CHROMIUM_PATH` مسیر را دستی بدهید.

## یک ایراد شناخته‌شده در انتخاب عناصر

`page.getByLabel('نام کاربری')` کار **نمی‌کند**. علتش تست نیست، خود برنامه
است: MudBlazor 6.21.0 برچسب را با `for="mudinput-{guid}"` می‌سازد ولی هیچ
`id` ای روی `<input>` نمی‌گذارد، پس اتصال برچسب به ورودی شکسته است.

این یک ایراد دسترس‌پذیری واقعی است — صفحه‌خوان نمی‌تواند بگوید هر فیلد چیست
و کلیک روی برچسب فوکوس را به ورودی نمی‌برد — و روی **همه‌ی فرم‌های برنامه**
اثر دارد، نه فقط صفحه ورود.

تا وقتی رفع نشده، از کمکی `field(page, 'نام برچسب')` در `helpers/app.js`
استفاده کنید که از روی ساختار DOM خود MudBlazor ورودی را پیدا می‌کند.

# ابزار راستی‌آزمایی حقوق و دستمزد (PAY2)

`pay2_audit.py` اعداد ذخیره‌شده در فیش‌های حقوقی را در برابر قواعد موتور محاسبه
و تنظیمات `PAY2_CONFIG` بررسی می‌کند. به دیتابیس وصل نمی‌شود — یک فایل JSON
می‌گیرد، پس روی هر ماشینی (حتی بدون SQL Server) اجرا می‌شود.

## طرز استفاده

```bash
# ۱. در SSMS اسکریپت خروجی را اجرا کنید و نتیجه را ذخیره کنید
#    Server/Tools/pay2_export.sql  →  pay2_export.json

# ۲. بررسی
python3 Server/Tools/pay2_audit.py pay2_export.json
```

خروجی دو بخش دارد:

* **✗ / ✓ خطای حسابی** — معادله‌های موتور محاسبه. اگر اینجا ✗ ببینید یعنی
  موتور یا داده خراب است و باید قبل از پرداخت بررسی شود. خروج با کد `1`.
* **⚠ هشدار** — داده و گردش کار. لزوماً باگ نیست ولی باید نگاه شود.
  با سوییچ `--strict` این‌ها هم باعث خروج با کد `2` می‌شوند.

## چه چیزهایی بررسی می‌شود

**معادله‌های حسابی (خطا)**

| بررسی | قاعده |
|---|---|
| خالص = ناخالص − کسورات | در موتور نسخه ۳ دقیقاً برقرار است؛ مانده گرد کردن در `ROUNDING_ADJ` داخل ناخالص می‌نشیند |
| تفکیک کسورات | `TOTAL_DED = INS_WORKER + TAX_AMOUNT + LOAN_DED + ADVANCE_DED + OTHER_DED` |
| بیمه سهم کارگر | `INS_BASE × INS_WORKER_RATE` |
| بیمه سهم کارفرما | `INS_EMPLOYER = INS_EMPLOYER_BASE + INS_UNEMPLOYMENT`، هرکدام با نرخ خودش |
| گرد کردن خالص | `NET_PAY` مضرب `ROUND_MODE` |
| سقف بیمه | `INS_BASE ≤ INS_CEILING_MONTHLY × روز ÷ ۳۰` |
| ناخالص در برابر آیتم‌ها | جمع آیتم‌های نوع ۱ و ۲ + `ROUNDING_ADJ` |
| بازسازی مبنای بیمه | جمع `INS_SUBJECT_AMOUNT` با اعمال سقف |
| مالیات | مبنای ماهانه از جدول `PAY2_TAX_BRACKET` سال جاری |

**هشدارها**

* **هماهنگی روزهای کارکرد** — مهم‌ترین بررسی. اگر در `PAY2_ATTENDANCE`
  یکی از `DAYS` (روز رسمی) یا `DAYSB` (روز اسمی) صفر و دیگری غیرصفر باشد،
  فیش خراب می‌شود بدون اینکه هیچ خطایی داده شود. دو حالت دارد:
  * `DAYS>0 , DAYSB=0` ← پرداختی صفر می‌شود ولی بیمه کامل کسر می‌شود
    ⇒ فیش با **خالص منفی**.
  * `DAYSB>0 , DAYS=0` ← حقوق پرداخت می‌شود ولی بیمه و مالیات صفر می‌ماند.

  توجه: ستون `WORK_DAYS` در `PAY2_ATTENDANCE` مبنای محاسبه **نیست** و
  می‌تواند با این دو ستون نخواند.
* **فیش منفیِ نهایی‌شده** — فیش با خالص منفی که `STATUS=3` گرفته و به سند
  حسابداری رفته است. گارد `SP_PAY2_GEN_DEED` خالص منفی را برای پرسنلِ
  «فقط‌بیمه» (کارکرد صفر و بدون وام/مساعده/سایر) مجاز می‌داند؛ اگر
  علتِ صفر بودن کارکرد در واقع همان ستون `DAYSB` باشد، این استثنا به‌اشتباه
  فعال می‌شود.
* **دو ریل حقوق اسمی/رسمی** — جایی که `BASE_SAL` و `BASE_SAL_B` مبلغشان
  فرق دارد. در موتور فعلی **ناخالص پرداختی روی ریل رسمی** (`BASE_SAL_B`)
  و **مبنای بیمه روی ریل اسمی** (`BASE_SAL`) محاسبه می‌شود، و
  `NOMINAL_GROSS` ناخالص ریل اسمی را نگه می‌دارد.
* **موتور قدیمی** — فیش‌های قبل از نسخه ۳ که ستون `ROUNDING_ADJ` ندارند و
  مانده‌ی گرد کردن (کمتر از ۵۰۰ ریال) در ناخالصشان ثبت نشده است.
* **مشمولیت آیتم‌ها**، **کیفیت داده**، **گردش کار** — موارد قابل بازبینی.

## هشدار محرمانگی

خروجی JSON داده‌های واقعی پرسنل دارد (نام، کد ملی، حقوق، شماره حساب).
`pay2_export.json` در `.gitignore` است؛ بعد از بررسی پاکش کنید.
